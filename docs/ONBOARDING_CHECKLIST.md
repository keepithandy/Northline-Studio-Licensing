# Split-License Onboarding Checklist

This checklist is operational guidance, not legal advice or certification. The controlling terms remain the applicable project and file licenses.

- [ ] Add a repository `LICENSE` file for source-code terms.
- [ ] Add a README scope note distinguishing code, creative assets, and third-party material.
- [ ] Add or link the controlling creative-content terms.
- [ ] Create a third-party attribution record using `THIRD_PARTY_ATTRIBUTION_TEMPLATE.md`.
- [ ] Create an asset provenance record using `ASSET_PROVENANCE_TEMPLATE.md`.
- [ ] Add the project to `PROJECTS.md` with status, authority, attribution location, and review date.
- [ ] Add a public permission-request path and a private alternative for confidential details.
- [ ] Check all local links with `python tools/check_links.py`.
- [ ] Complete `PROJECT_AUDIT_CHECKLIST.md`.
- [ ] Record reviewer name, review date, unresolved items, and final human sign-off.

When summaries conflict, project-specific and file-specific terms control.
